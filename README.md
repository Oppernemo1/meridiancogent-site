# MeridianCogent — marketing site

Pre-launch marketing website for **MeridianCogent**, an M&A execution platform
currently in development.

Standalone project. It does not import from or connect to any other codebase.

## Stack

- **Next.js 14** (App Router). Every page is statically rendered; the only
  server code is the `/api/early-access` route handler, which runs as a
  serverless function on Vercel. (`output: 'export'` is intentionally **not**
  used, because that mode cannot host the Resend form endpoint.)
- **Tailwind CSS** with `@tailwindcss/typography` for article styling.
- **MDX** blog content as `.mdx` files in `content/resources/` — no CMS, no
  database. Frontmatter drives each article's `<title>`, meta description and
  Open Graph tags.
- **Resend** for the early access list + transactional email.
- **Vercel Analytics** (privacy-friendly, no cookie banner). Nothing else.

## Local development

```bash
npm install
cp .env.example .env.local   # fill in the Resend values
npm run dev                  # http://localhost:3000
```

`npm run build && npm start` to run a production build locally.

## Environment variables

Set these in Vercel (Project → Settings → Environment Variables) and in
`.env.local` for local development. See `.env.example`.

| Variable | Required | Purpose |
| --- | --- | --- |
| `RESEND_API_KEY` | yes | Resend API key. **Never commit this.** |
| `RESEND_SEGMENT_ID` | yes | Resend Segment the contact is added to. (`RESEND_AUDIENCE_ID` is read as a fallback.) |
| `RESEND_FROM_EMAIL` | recommended | Verified sender. Defaults to `MeridianCogent <noreply@meridiancogent.com>`. |
| `INTERNAL_NOTIFICATION_EMAIL` | optional | Role address that gets a note on each signup. Defaults to `hello@meridiancogent.com`. |
| `NEXT_PUBLIC_SITE_URL` | recommended | Canonical origin, no trailing slash. Defaults to `https://www.meridiancogent.com`. Drives canonical URLs, `sitemap.xml`, OG tags. |

The early access form works without Resend configured only insofar as it will
return a clear error state — no signups are stored until the keys are set.

### Resend contact properties

The form writes `company`, `role` and `source` as custom properties on the
Resend contact. Resend rejects any contact create/update that names a
property the account doesn't have, so the form fails until they exist. Create
them once per Resend account (idempotent, safe to re-run) before deploying:

```bash
node --env-file=.env.local scripts/setup-resend-properties.mjs
```

## Content: adding a resource article

1. Create `content/resources/<slug>.mdx`.
2. Include frontmatter:

   ```mdx
   ---
   title: "Article title"
   description: "One-sentence summary used for <title>, meta description and OG."
   date: "2026-09-30"
   tags: ["TSA"]            # any of: TSA, Integration, Carve-out, Playbooks
   readingTime: "6 min"     # optional; auto-estimated if omitted
   ---
   ```

3. Write the body in Markdown/MDX. The file's name is the URL slug
   (`/resources/<slug>`). It is picked up automatically by the index,
   the homepage preview, `sitemap.xml`, related-articles, and its generated
   OG image — no other wiring needed.

## SEO / technical notes

- `robots.txt` — generated by `src/app/robots.ts` (allows all public routes,
  disallows `/api/`).
- `sitemap.xml` — generated by `src/app/sitemap.ts`, includes every resource
  article.
- Per-page `<title>` / meta description / canonical / Open Graph / Twitter card
  via the App Router Metadata API; article metadata comes from MDX frontmatter.
- Open Graph images are generated at build time with `next/og`
  (`opengraph-image.tsx`), one per article driven by frontmatter.
- Organization JSON-LD is on the homepage only. No `SoftwareApplication`
  schema, no pricing data anywhere.
- Fonts are system fonts only (Georgia serif headings, Helvetica/Arial UI) —
  zero web-font requests, nothing render-blocking.

## Brand assets

`public/logo-full.svg` (header lockup), `public/logo-full-ice.svg` (for dark
backgrounds), `public/logo-mark.svg` (icon mark). The favicon is generated from
`src/app/icon.svg` (the mark).

## Deploy

Push to a Git repo connected to Vercel, or `vercel` from the CLI. Framework
preset: **Next.js** (no special build settings). Add the environment variables
above before the first deploy.
